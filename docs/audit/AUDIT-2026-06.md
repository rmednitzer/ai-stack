# Deep Audit — ai-stack (2026-06)

**Audit date:** 2026-06-07 · **Chart version at audit:** 2.10.0
**Scope:** the entire repository — Helm templates, `values*.yaml`, `_helpers.tpl`,
`tests/`, CI/CD (`.github/`), supply-chain artifacts (`sbom.cdx.json`, `zarf.yaml`),
`files/` payloads, and all `docs/`.

This is a point-in-time snapshot (like an ADR — not version-tracked). It records
what was reviewed, what was fixed in 2.10.0, the prioritised backlog of verified
findings deferred to dedicated changes, and the findings that were **assessed and
dismissed** so they are not re-investigated.

---

## 1. Method

Three parallel read-only audits (templates+values, docs+compliance, CI+supply-chain)
fanned out across the repo. **Every finding was then re-verified against the source
files before any action** — a discipline that mattered: a meaningful fraction of
the raw findings were false or overstated, mostly from (a) ignoring the additive
global default-deny NetworkPolicy, and (b) stale knowledge of 2026 GitHub Action
major versions. The chart is **mature and secure-by-default**; this audit found no
critical hole in the shipped defaults. Conclusions are in §2–§4.

Nothing was dropped from the chart: every component is opt-in and serves a distinct
role; there is no dead component to remove. "Optimisation" here means tightening,
documenting, and right-sizing — not deletion.

## 4. Assessed and dismissed (do not re-chase)

Recorded so future audits don't re-raise these. Each was investigated and found
**false, overstated, or an intentional documented design choice**.

- **"Qdrant / Valkey have unrestricted egress → data exfiltration."** *False.* The
  namespace-wide `default-deny` NetworkPolicy (Ingress **and** Egress) plus
  `allow-dns` already restrict every `part-of: ai-stack` pod to DNS-only egress;
  the Ingress-only per-component policies are additive, not a replacement.
- **"Ollama Deployment is missing its ArgoCD sync-wave."** *False / by design.*
  Platform-tier datastores (Ollama, Qdrant, Valkey, Postgres, …) correctly use the
  default wave (`0`); only app-tier workloads carry `sync-wave: app` (`5`). Tested
  in `tests/sync_waves_test.yaml`.
- **"`global.repoSlug` has no default → broken runbook URLs."** *False.*
  `prometheusrules.yaml` uses `| default "rmednitzer/ai-stack"`.
- **"Grype fails open on critical CVEs."** *Intentional & documented.* CI **warns**
  on critical upstream CVEs by design (README CI table); upstream image CVEs do not
  block releases of the chart.
- **"syft-sbom / cve-scan skip PRs."** *Intentional.* Deep per-image SBOM + CVE
  scans run on merge to `main` (AGENTS.md §5); the committed SBOM is parity-checked
  on every PR.
- **"Action version comments are wrong (checkout v6 / setup-python v6 / upload-artifact v7 don't exist)."**
  *False — stale knowledge.* These are the current 2026 majors (git history shows
  `actions/checkout` 4.3.1→6.0.3; CHANGELOG 2.9.0 pins `setup-python@v6.2.0`).
- **"SearXNG is missing its security-exception annotation."** *False.* Present at
  `templates/searxng/deployment.yaml` (`assurance.platform/security-exception:
  searxng-requires-root`). The root requirement is upstream and tracked in
  `.kube-linter.yaml`.
- **"OTel debug exporter at verbosity `detailed` may log secrets."** *False.*
  Verbosity is `basic`, lab-profile only, and the `redaction` processor runs ahead
  of every exporter — debug receives already-redacted data.
- **"OTel zpages exposed without auth."** *Negligible.* Port `55679` is not in the
  OTel NetworkPolicy ingress allowlist, so default-deny blocks it; binding to
  localhost is an optional defense-in-depth nicety (folded into R-class follow-ups).

|-----------|------------|
| Pod / workload security | **Strong** — PSS Restricted with few, annotated, upstream-driven exceptions |

| Cost awareness | **Good** — requests/limits + HPA/PDB; GPU right-sizing now documented |
