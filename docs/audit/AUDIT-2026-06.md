# Deep Audit — ai-stack (2026-06)

**Audit date:** 2026-06-07 · **Chart version at audit:** 2.10.0
**Scope:** the entire repository — Helm templates, `values*.yaml`, `_helpers.tpl`,
`tests/`, CI/CD (`.github/`), supply-chain artifacts (`sbom.cdx.json`, `zarf.yaml`),
`files/` payloads, and all `docs/`.

This is a point-in-time snapshot (like an ADR — not version-tracked). It records
what was reviewed, what was fixed in 2.10.0, the prioritised backlog of verified
findings deferred to dedicated changes, and the findings that were **assessed and
dismissed** so they are not re-investigated.

---

## 1. Method

Three parallel read-only audits (templates+values, docs+compliance, CI+supply-chain)
fanned out across the repo. **Every finding was then re-verified against the source
files before any action** — a discipline that mattered: a meaningful fraction of
the raw findings were false or overstated, mostly from (a) ignoring the additive
global default-deny NetworkPolicy, and (b) stale knowledge of 2026 GitHub Action
major versions. The chart is **mature and secure-by-default**; this audit found no
critical hole in the shipped defaults. Conclusions are in §2–§4.

Nothing was dropped from the chart: every component is opt-in and serves a distinct
role; there is no dead component to remove. "Optimisation" here means tightening,
documenting, and right-sizing — not deletion.

## 4. Assessed and dismissed (do not re-chase)

Recorded so future audits don't re-raise these. Each was investigated and found
**false, overstated, or an intentional documented design choice**.

- **"Qdrant / Valkey have unrestricted egress → data exfiltration."** *False.* The
  namespace-wide `default-deny` NetworkPolicy (Ingress **and** Egress) plus
  `allow-dns` already restrict every `part-of: ai-stack` pod to DNS-only egress;
  the Ingress-only per-component policies are additive, not a replacement.
- **"Ollama Deployment is missing its ArgoCD sync-wave."** *False / by design.*
  Platform-tier datastores (Ollama, Qdrant, Valkey, Postgres, …) correctly use the
  default wave (`0`); only app-tier workloads carry `sync-wave: app` (`5`). Tested
  in `tests/sync_waves_test.yaml`.
- **"`global.repoSlug` has no default → broken runbook URLs."** *False.*
  `prometheusrules.yaml` uses `| default "rmednitzer/ai-stack"`.
- **"Grype fails open on critical CVEs."** *Intentional & documented.* CI **warns**
  on critical upstream CVEs by design (README CI table); upstream image CVEs do not
  block releases of the chart.
- **"syft-sbom / cve-scan skip PRs."** *Intentional.* Deep per-image SBOM + CVE
  scans run on merge to `main` (AGENTS.md §5); the committed SBOM is parity-checked
  on every PR.
- **"Action version comments are wrong (checkout v6 / setup-python v6 / upload-artifact v7 don't exist)."**
  *False — stale knowledge.* These are the current 2026 majors (git history shows
  `actions/checkout` 4.3.1→6.0.3; CHANGELOG 2.9.0 pins `setup-python@v6.2.0`).
- **"SearXNG is missing its security-exception annotation."** *False.* Present at
  `templates/searxng/deployment.yaml` (`assurance.platform/security-exception:
  searxng-requires-root`). The root requirement is upstream and tracked in
  `.kube-linter.yaml`.
- **"OTel debug exporter at verbosity `detailed` may log secrets."** *False.*
  Verbosity is `basic`, lab-profile only, and the `redaction` processor runs ahead
  of every exporter — debug receives already-redacted data.
- **"OTel zpages exposed without auth."** *Negligible.* Port `55679` is not in the
  OTel NetworkPolicy ingress allowlist, so default-deny blocks it; binding to
  localhost is an optional defense-in-depth nicety (folded into R-class follow-ups).

No Critical defect in the default deployment. F-2 is High but rides an opt-in
component (`authelia.enabled=false`); it is a real break for anyone enabling SSO.

### F-1 — MCPO probes hit `GET /` (404), so the pod never becomes Ready

MCPO is a FastAPI gateway that mounts a sub-app per configured MCP server; it
defines **no** `GET /`, `/health`, or `/healthz` on the root app (validated
against `open-webui/mcpo`), so `/` returns 404 and the readiness probe never
passes — MCPO is unreachable through its Service even when healthy. **Fix:**
probe the FastAPI-generated `/openapi.json` (200, no external Swagger assets,
present even with empty `mcpServers`). Pinned by `tests/mcpo_test.yaml`.

### F-2 — Authelia OIDC `client_secret` used disabled `${VAR}` expansion

The config rendered `client_secret: $plaintext$${AUTHELIA_OIDC_CLIENT_SECRET}`
and the Deployment injected the secret as an env var. Authelia's `${VAR}`
substitution is **off by default**, and the `expand-env` filter that re-enables
it is **deprecated and removed in v4.40** (startup error). On 4.39.20 the literal
placeholder becomes the client secret, so OIDC login fails. An OIDC client
secret is a config **list item**, so it cannot use the `_FILE` convention the
other Authelia secrets use. **Fix:** the forward-looking `template` filter
(`X_AUTHELIA_CONFIG_FILTERS=template`) reads the secret from a mounted file via
the `secret` function:
`client_secret: '$plaintext${{ secret "/secrets/oidc-client-secret" }}'`. The
env injection is removed and the file added to the projected secrets volume, so
the value no longer appears in the pod env or the rendered manifest (a
defense-in-depth gain). Open WebUI still consumes the **raw** secret from the
same key (correct for the relying party). Validated against `authelia/authelia`.
Pinned by `tests/authelia_oidc_test.yaml`.

### F-3 — Agent `deps` `emptyDir` unbounded

The Pydantic AI and ingestion-worker pods install their dependency tree into a
`deps` `emptyDir` whose `tmp` sibling is bounded but `deps` was not — an
unbounded `emptyDir` can exhaust node ephemeral storage and evict unrelated
pods. **Fix:** `sizeLimit: 1Gi` on both (ample for the resolved trees). The
persistence-fallback data `emptyDir`s (Postgres/Qdrant/Ollama) are deliberately
left unbounded: that is the lab-only `persistence.enabled=false` path for stores
whose size is unbounded by design. Pinned by `tests/hardening_test.yaml`.

### F-4–F-8 — supply-chain parity, doc accuracy, freshness

- **F-4:** SBOM Valkey `boundary` aligned `cache` → `storage` to match the
  `_helpers.tpl` governance map (the rendered label asserted by

  unchanged.
- **F-5:** `LICENSE_COMPLIANCE.md` re-aligned to `values.yaml`: Ollama

  takes precedence; tracing is off-by-default regardless, so never a leak —

- **F-7:** removed a duplicated `mcpo.config` comment in `values.yaml`.
- **F-8:** qualified the OTel PII-redaction control in `EU_COMPLIANCE_CHECK.md`

## 8. Verified non-findings (overturned on second look)

- **N-1 — "Tika has unrestricted egress (SSRF/XXE)."** *Rejected.* Tika carries
  `part-of: ai-stack`, and `networkPolicy.enabled` is `true`, so the shared
  `default-deny` already isolates Tika on **both** directions and
  `allow-dns`/`allow-otel-egress` re-permit only DNS + the collector. Kubernetes
  NetworkPolicies are additive-allow, so Tika's `Ingress`-only policy **cannot
  open** egress; the outbound path is already closed. Adding `- Egress` would be
  a no-op. (This is the same additive-default-deny reasoning that cleared the
  Qdrant/Valkey egress alarm in the 2026-06-07 pass, §4.)
- **N-2 — "OTel redaction off by default."** *Rejected.*
  `global.otel.redaction.enabled` is `true`; OTel itself is opt-in, so nothing
  flows by default and redaction is on when it does. Pinned by
  `tests/hardening_test.yaml`.
- **N-3 — "SearXNG rate-limiter disabled."** *Rejected (intentional).* Enabling
  the limiter rejects Open WebUI's server-side JSON queries and breaks web
  search; documented trade-off.
- **N-4 — "LangGraph `/ok` probe wrong."** *Rejected.* `langgraph-server`
  exposes `/ok`; the probe is correct.

## 9. Adversarial review

The threat model (`SECURITY.md`) treats the model-driven plane (Open WebUI,
MCPO, Open Terminal, RAG, web search, agent tool-use) as attacker-influenced.
Result against that model:

- **Lethal trifecta.** Default-deny + per-component least-privilege egress is
  the containment; the residual exfiltration surface is the unscoped `:443`/`:80`
  egress the agent/worker need for PyPI and model providers (A-1), bounded by the
  operator FQDN control (B6). MCPO/Open Terminal are off by default.
- **Indirect prompt injection (web/RAG).** Web search is off in the base chart
  (on only in `values-full.yaml`, explicit opt-in) because web content is
  attacker-influenced; RAG content is treated the same.
- **SSRF/XXE from Tika.** Contained by default-deny egress (N-1), not by anything
  Tika-specific.
- **Secret handling.** No hardcoded secrets; per-component Secrets;
  `automountServiceAccountToken: false`; the F-2 fix removes the last credential
  riding a pod env var; Open WebUI tool-server keys stay out of pod manifests
  (POL-002, admin-UI step).
- **Supply chain.** Digest-pinned images (incl. CNPG, R1), blocking Grype gate
  with guarded time-boxed exceptions, cosign-keyless chart signing, SBOM parity
  (now incl. F-4), hashed Python locks (R7).
- **Privilege/runtime.** PSA `restricted`, dropped capabilities, non-root (Tika
  the one annotated exception), read-only root FS where the app allows; hardened
  `runtimeClassName` is an operator opt-in (A-2).

The secure-by-default floor held under each scenario.

## 11. Conclusion

The chart remains **mature and secure-by-default**. The 2026-06-07 backlog is
essentially closed; this pass found one High availability bug (F-1) and one High
opt-in correctness bug (F-2), both fixed and test-pinned, plus minor parity and
documentation corrections. No security default was weakened. Remaining
operator-owned surfaces (A-1..A-7) are deliberate and documented.
