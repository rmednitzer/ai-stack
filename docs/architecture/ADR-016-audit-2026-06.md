## Context

After wiring the full deployment into Open WebUI (ADR-015), the directive was to
audit the entire repository in depth, perform an adversarial review, and validate
everything against trusted sources and known-good patterns. A full-pass audit was
run with the same discipline as the 2026-06-07 pass: every candidate finding was
re-verified against the rendered manifests and the upstream source/docs of the
component before any change. The detail, severity table, non-findings, and
adversarial-review scenarios are in [AUDIT-2026-06.md](../audit/AUDIT-2026-06.md);
this ADR records the decisions.

The 2026-06-07 backlog (R1–R10) was found essentially closed at 2.12.0 (CNPG
pinning + SBOM/Zarf parity, hashed worker locks, ingress scoping, Valkey AUTH,
the connection-test digest, and the Open WebUI key split are all done). The new
pass surfaced two High-severity defects and a set of minor parity/precision
issues. Two plausible findings were overturned as false positives.

Constraints honoured: never weaken a default; `values.yaml` is the source of
truth; surgical changes; validate against trusted sources; assert security-
relevant behaviour in `tests/` (CLAUDE.md principle 3); POL-002 (no inline
credentials in workload manifests).

## Decision

1. **MCPO probes target `/openapi.json`, not `/` (F-1).** MCPO is a FastAPI
   gateway with no `GET /` route (it returns 404), validated against
   `open-webui/mcpo`. Probing `/` failed readiness so the pod never became
   Ready. `/openapi.json` returns 200, needs no external Swagger assets, and is
   present even with an empty `mcpServers`.

2. **Authelia OIDC client secret is read from a file via the `template` config
   filter (F-2).** Authelia's legacy `${VAR}` expansion is off by default and the
   `expand-env` filter is deprecated (removed in v4.40), so
   `client_secret: $plaintext$${AUTHELIA_OIDC_CLIENT_SECRET}` used the literal
   placeholder and broke SSO. An OIDC client secret is a config list item and
   cannot use the `_FILE` convention. Set `X_AUTHELIA_CONFIG_FILTERS=template`
   and read the mounted secret with the `secret` function:
   `client_secret: '$plaintext${{ secret "/secrets/oidc-client-secret" }}'`. The
   `AUTHELIA_OIDC_CLIENT_SECRET` env injection is removed and the key added to
   the projected secrets volume, so the value no longer appears in the pod env or
   the rendered manifest. Open WebUI continues to consume the raw secret from the
   same key (correct for the relying party). Validated against `authelia/authelia`.

3. **Bound the agent `deps` emptyDir volumes (F-3).** Add `sizeLimit: 1Gi` to the
   Pydantic AI and ingestion-worker `deps` install targets, matching their
   already-bounded `tmp` siblings, so a runaway/compromised `pip install` cannot
   exhaust node ephemeral storage. The persistence-fallback data emptyDirs
   (Postgres/Qdrant/Ollama) stay unbounded by design (lab-only
   `persistence.enabled=false` path for stores of unbounded size).

4. **Restore artifact and documentation parity (F-4..F-8).** Align the SBOM
   Valkey `boundary` to the canonical governance map (`cache` → `storage`);
   re-align three stale `LICENSE_COMPLIANCE.md` versions to `values.yaml`;
   canonicalise the LangGraph tracing var to `LANGSMITH_TRACING`; remove a
   duplicated `mcpo.config` comment; qualify the OTel PII-redaction compliance
   claim to telemetry-enabled and append a dated `EU_COMPLIANCE_CHECK.md`
   validation note (historical entries left intact).

5. **Record the overturned findings (N-1..N-4).** Tika egress is already closed
   by the additive default-deny + allow-dns/allow-otel-egress trio (no Tika
   change); OTel redaction is on by default when telemetry is on; the SearXNG
   limiter is intentionally off; the LangGraph `/ok` probe is correct.

6. **Pin the behaviour in tests.** `tests/mcpo_test.yaml` (probe path),
   `tests/hardening_test.yaml` (both `deps` bounds), and the new
   `tests/authelia_oidc_test.yaml` (template-filter wiring, no `${VAR}`, no env
   injection, file mount). 122 tests total.

## Consequences

**Positive**

- MCPO becomes usable (it never reached Ready before); enabling Authelia SSO now
  actually authenticates. Both High defects are fixed and test-pinned.
- The Authelia change also removes the last credential that rode a pod env var,
  moving it to a mounted file — a defense-in-depth gain beyond the bug fix.
- Node ephemeral storage is protected from a runaway dependency install.
- SBOM/governance and docs are back in parity; compliance claims are precise.

**Negative**

- Enabling the `template` config filter means Authelia templates the whole
  config file; any future literal `{{ … }}` added to the Authelia config must be
  escaped. The single intended `{{ secret … }}` is emitted via a Helm raw-string
  literal and asserted by a test.
- The OIDC secret remains `$plaintext$` (auto-generated secrets cannot be hashed
  at template time). Hashed secrets are the hardening follow-up (revisit trigger).

**Neutral**

- No image, `Chart.yaml` version, or `zarf.yaml` change; the SBOM change is a
  property-value alignment, not a component change. Accrues in `CHANGELOG.md`
  `[Unreleased]`.
- The probe-path and tracing-var changes alter rendered output for the affected
  opt-in components only; default (lab) renders are otherwise unchanged.

## Alternatives considered and rejected

- **Re-enable Authelia `${VAR}` via `expand-env` (minimal change).** Rejected:
  `expand-env` is deprecated and removed in v4.40, so it would break on the next
  Authelia major. The `template` filter is the forward-looking path.
- **Hash the OIDC client secret at template time.** Rejected: Helm cannot run
  `authelia crypto hash`, and the chart auto-generates the secret; a pre-computed
  hash would defeat auto-generation. Left as an operator hardening option.
- **Add `- Egress` to the Tika NetworkPolicy (the "obvious" SSRF fix).**
  Rejected: a verified no-op. The additive default-deny already constrains Tika
  egress to DNS + OTel; Tika's `Ingress`-only policy cannot open egress.
- **Probe MCPO `/docs` instead of `/openapi.json`.** Rejected: `/docs` returns an
  HTML page that references Swagger UI assets; `/openapi.json` is a small JSON
  payload with no external dependency and the same 200 guarantee.
- **Bound the persistence-fallback data emptyDirs too.** Rejected: those back
  databases/model stores of unbounded size in the lab-only ephemeral path; a
  small ceiling there would cause spurious pod eviction.

## Revisit triggers

- Open WebUI gains a way to reference tool-server credentials from a Secret (not
  inline JSON) — revisit auto-wiring MCPO (carried from ADR-015).
- A deployment standardises on hashed Authelia client secrets (e.g. an init job
  or operator-supplied hash) — revisit dropping `$plaintext$`.
- MCPO publishes a dedicated health endpoint — revisit the probe target.
- The agent/worker dependency trees grow materially — revisit the `1Gi` `deps`
  ceiling.
- Authelia changes the `template`/`secret` filter contract or the config-filter
  env var — re-validate the OIDC wiring.
