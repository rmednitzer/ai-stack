# ADR-010 — Consolidate dependency automation on Renovate (retire Dependabot)

- **Status:** Accepted
- **Date:** 2026-06-10
- **Deciders:** Roman Mednitzer (chart maintainer)
- **Chart version at acceptance:** 2.12.0 (`appVersion` 2026.5)
- **Supersedes:** ADR-001 §3 (the two-manager Renovate/Dependabot split), in part

---

## Context

[ADR-001 §3](ADR-001-component-version-management.md) recorded a deliberate
split: Renovate's `helm-values` manager bumped `values.yaml` / `values-prod.yaml`,
while `.github/dependabot.yml` handled the
`github-actions`, `docker` (Dockerfile), and — added per
[AUDIT-2026-06](../audit/AUDIT-2026-06.md) **R7** — `pip` ecosystems.

The split worked but bought no capability. Renovate's manager coverage is a
superset of the Dependabot ecosystems in use here: `github-actions`,
`dockerfile`, and `pip-compile` (which maintains `uv`-compiled, hashed,
universal `requirements.txt` locks). What the split did carry was standing
cost: two bot configs, two mental models, two PR-author identities in
`sync-image-artifacts.yml`'s same-repo-branch assumption, a tolerated
Renovate/Dependabot `docker`-ecosystem overlap (noted in `README.md`), and
duplicated review/label conventions. The rest of the fleet standardised on
Renovate; ai-stack was the lone two-bot repository.

A note on **AUDIT-2026-06 R7**: that audit recommended *adding* a Dependabot
`pip` entry to bring the ingestion-worker lock under hash-pinned management,
which was done. This ADR supersedes the *mechanism* (Dependabot) while
preserving the *intent* (both Python locks stay fully hashed and
bot-maintained) — Renovate's `pip-compile` manager now owns them. The audit
record is a point-in-time snapshot and is left unmodified; this ADR is the
forward record of the reversal.

## Decision

1. **Renovate is the single dependency-automation tool.** `renovate.json5`
   enables `helm-values`, `github-actions`, `dockerfile`, and `pip-compile`.
   `.github/dependabot.yml` is removed, along with its `CODEOWNERS` entry.

2. **The hashed-lock invariant is preserved.** The `uv`-compiled
   `files/pydanticai/requirements.txt` and `files/ingestion-worker/requirements.txt`
   locks carry `uv`'s standard autogenerated header recording the
   `uv pip compile --universal --generate-hashes` command. Renovate's
   `pip-compile` manager replays that exact command, so each update regenerates
   a universal, fully-hashed lock (the ADR-002 supply-chain posture, extended to
   Python deps). The `pydanticai` lock header — previously a custom block — is
   normalised to `uv`'s standard form so the manager detects it; **the locked
   pins and hashes are unchanged by this PR**. `pip-compile` updates require
   `uv` in the Renovate runtime (present in the Mend-hosted app; ensure it on
   any self-hosted runner).

3. **Action and base-image digest pinning are preserved.** `pinDigests: true`
   plus `config:best-practices` keep GitHub Actions and Dockerfile base images
   digest-pinned, consistent with [ADR-002](ADR-002-image-digest-pinning.md).
   Minor/patch action updates are grouped; majors stay individual. Cadence
   mirrors the retired Dependabot schedule (Actions Monday, Dockerfile + pip
   Wednesday, `Europe/Vienna`).

4. **Downstream-artifact discipline is unchanged.** Neither Renovate nor any bot
   updates `sbom.cdx.json` or `zarf.yaml`; the `sbom-validate` parity job and
   `sync-image-artifacts.yml` remain the enforcement path (ADR-001 §1 and the
   2026-05-27 Consequences update). `sync-image-artifacts.yml`'s
   same-repo-branch assumption now names only the Renovate App and maintainer
   pushes.

5. **Governance docs are treated as code (ADR-001 §2).** `SECURITY.md`,
   `README.md`, `EU_COMPLIANCE_CHECK.md`, `LICENSE_COMPLIANCE.md`,
   `EU_OPERATIONS_GUIDE.md`, and `ENTERPRISE_EVALUATION.md` are updated in this
   PR to name Renovate as the supply-chain dependency-update mechanism for
   Actions, Dockerfiles, and the Python locks.

## Consequences

**Positive**

- One tool, one config (`renovate.json5`), one PR-author identity. Removes the
  two-bot surface and the tolerated Renovate/Dependabot `docker`-ecosystem
  overlap.
- The Python locks gain the same digest-replay discipline as the images: hashes
  are regenerated by the recorded `uv` command rather than by a second bot.
- The dependency-update story is now uniform across the fleet.

**Negative / accepted trade-offs**

- Renovate's `pip-compile` manager depends on `uv` being available in the
  runtime; a self-hosted Renovate without `uv` would silently stop maintaining
  the locks. Mitigation: documented here and in `renovate.json5`; the
  Mend-hosted app ships `uv`.
- GitHub-native Dependabot **security updates** (the alerts surfaced in the
  Security tab) are independent of `dependabot.yml` and remain available at the
  repo/org setting level. This ADR retires only Dependabot **version updates**;
  keeping security alerts enabled is recommended and complementary.
- Dependabot's grouped-PR ecosystem labels are replaced by equivalent Renovate
  `packageRules` labels (`github-actions`, `container-images`, `python`).
